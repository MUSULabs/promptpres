# eval/ — สคริปต์คำนวณสถิติสำหรับบทที่ 3–4

ชุดคำสั่งที่เปลี่ยนไฟล์คำตอบจาก Google Forms / Excel เป็นตาราง Markdown (คัดลอกลงเล่มได้) และ CSV (เปิดใน Excel ได้)
ทุกคำสั่งรันจากโฟลเดอร์ `Code/promptpres` ค่าตัวเลขที่สคริปต์ใช้ (เกณฑ์ผ่าน IOC, ระยะคลาดเคลื่อนที่ยอมให้, ช่วงแปลผล SUS)
อยู่ใน [`config/eval-v0.yaml`](../config/eval-v0.yaml) พร้อมแหล่งที่มา

| คำสั่ง | ใช้เมื่อ | ได้ตารางสำหรับ |
|---|---|---|
| `python -m eval.ioc` | ผล IOC จากผู้เชี่ยวชาญ 5 ท่านกลับมา (27 พ.ย.) | บทที่ 3: ค่า IOC รายข้อ รายเกณฑ์ ทั้งฉบับ และข้อเสนอแนะ |
| `python -m eval.calibrate` | มีผลวิเคราะห์ใน `data/runs` มากพอ (ม.ค.) | บทที่ 4: การกระจายของค่าแยกตามฉาก, ฉากควบคุมเทียบ S01, ค่าขอบระดับที่แนะนำสำหรับ thresholds-v1 |
| `python -m eval.measurement_eval` | คนในทีมนับเสียงเติมและคำติดปาก / ช่วงหยุด ฯลฯ เสร็จ (ม.ค.) | บทที่ 4: ความแม่นยำของการวัด |
| `python -m eval.agreement_and_sus levels` | อาจารย์ 3 ท่านให้ระดับคลิปเสร็จ (15 ม.ค.) | บทที่ 4: ความสอดคล้องของระดับ |
| `python -m eval.agreement_and_sus sus` | แบบสอบถาม SUS ปิดรับ (20 ม.ค.) | บทที่ 4: ความพึงพอใจในการใช้งาน |

ติดตั้ง (ถ้ายังไม่มี): `pip install -r eval/requirements.txt`

## แผนการประเมิน 3 ส่วน (รูบริก v0.9)

| ส่วน | ผู้ให้ข้อมูล | ไฟล์ที่กรอก | คำสั่ง |
|---|---|---|---|
| 1. ความตรงของเกณฑ์ (IOC) | ผู้เชี่ยวชาญ 5 ท่าน 16 ข้อ | `ioc_responses.csv` หรือไฟล์จาก Google Forms | `eval.ioc` |
| 2. ความแม่นของการวัดและความสอดคล้องของระดับ | ทีมนับเหตุการณ์ (S2 S3) · ผู้ประเมิน 3 ท่านให้ระดับ 1–4 บนคลิปคัดสรร | `gt_values.csv`, `ratings.csv` | `eval.measurement_eval`, `eval.agreement_and_sus levels` |
| 3. ความสามารถในการใช้งาน (SUS) | ผู้ใช้ 15–30 คน | `sus_responses.csv` | `eval.agreement_and_sus sus` |

คลิปคัดสรรสำหรับส่วนที่ 2 อยู่ใน [`config/eval_clips_sc02.yaml`](../config/eval_clips_sc02.yaml) (8 คลิปจาก SC02 คลิปละ 1–3 นาที — ผู้วิจัยยืนยันสิทธิ์ส่งบทถอดเสียงและหัวข้อแล้ว 17 พ.ย. 2569, D-058)
รหัสรอบอยู่ใน [`templates/eval_clip_ids.txt`](templates/eval_clip_ids.txt) ตรวจไฟล์จริง หัวข้อ เวลาเป้าหมาย และ SHA-256 ด้วย
`python -m eval.run_sc02 --preflight` หลังผู้วิจัยตรวจสิทธิ์ครบทั้ง 8 คลิปสำหรับการส่งบทถอดเสียงและหัวข้อไป OpenRouter/Gemini
ให้ใช้ `python -m eval.run_sc02 --allow-openrouter` เพื่อประมวลผลใหม่โดยไม่ใช้ cache ชุดพัฒนา
รันครบ 8 คลิปแล้ว 17 พ.ย. 2569 (D-058) สคริปต์ไม่เขียนทับโฟลเดอร์ผล ถ้าต้องรันใหม่ให้ย้ายโฟลเดอร์เดิมออกก่อน
ผลอยู่ใน `data/eval_sc02_v0_9/` เทียบกับแบบตอบจริงด้วย `--runs data/eval_sc02_v0_9` และใช้ `sc02.md` เป็นตารางผลระบบ
`--preflight --pack-input` สร้างไฟล์ข้อมูลเฉพาะใน `data/` สำหรับสคริปต์สร้างชุดผู้ประเมินใน Vault

ชื่อเกณฑ์และสิ่งที่วัด (ใช้ถ้อยคำเดียวกันในฟอร์มของผู้ประเมิน):

| รหัส | ชื่อ (v0.9) | สิ่งที่ระบบวัด |
|---|---|---|
| C1 | ลำดับหัวข้อเทียบกับแผน | ลำดับที่อธิบายแต่ละหัวข้อครั้งแรก เทียบกับลำดับที่ยืนยันไว้ |
| C2 | ความครอบคลุมเชิงความหมาย | ร้อยละของหัวข้อที่อธิบายชัดเจน |
| S1 | อัตราการพูด | พยางค์ต่อวินาที ไม่รวมช่วงเงียบและเสียงเติม |
| S2 | การหยุดพูดยาว | จำนวนช่วงเงียบ ≥ 2 วินาทีต่อนาที และช่วงที่นานที่สุด |
| S3 | เสียงเติมและคำติดปาก | เสียงเติมช่วงหยุด (เอ่อ อ่า อืม เอิ่ม) และวลีติดปากฟุ่มเฟือยตามบริบท ต่อนาที |
| N1 | การใช้ท่าทางมือประกอบการพูด | ช่วงมือนิ่งต่อเนื่องเทียบความกว้างไหล่ (จำนวนช่วงต่อนาทีและช่วงที่นานที่สุด) |
| N2 | การหันหน้าสื่อสารกับผู้ฟัง | ทิศทางศีรษะเทียบกับแนวกล้อง (ร้อยละเวลาที่หันหน้าตรง) ไม่ใช่การสบตา |
| T1 | เวลาเทียบเป้าหมาย | ร้อยละที่เวลาพูดจริงต่างจากเวลาเป้าหมาย |

กติกานับ S3 สำหรับผู้นับ (ตรงกับ `config/pipeline-v0.yaml` หัวข้อ `fillers`):
- เสียงเติม เอ่อ อ่า อืม เอิ่ม (และ uh um) ที่ต่อเนื่องกันนับ 1 ครั้ง · "เออ" ที่แปลว่าใช่ไม่นับ
- วลีติดปาก 8 วลี: แบบว่า ก็แบบ ก็แบบว่า คือแบบ คือแบบว่า แบบคือ อะไรอย่างนี้ อะไรแบบนี้ (ตรงหลายวลีนับวลีที่ยาวที่สุดครั้งเดียว)
- คำว่า แบบ ก็คือ คือ นับเฉพาะเมื่อพูดซ้ำติดกัน ("คือ คือ" = 1 ครั้ง) หรืออยู่ติดเสียงเติมไม่เกิน 0.5 วินาที ("เอ่อ แบบ" = 2 ครั้ง)
- ไม่นับคำที่ใช้ตามความหมายปกติ เช่น การออกแบบระบบ แบบประเมิน แบบจำลอง กล่าวคือ

## เตรียมไฟล์

1. Google Forms: แท็บ "การตอบกลับ" → ⋮ → "ดาวน์โหลดคำตอบ (.csv)" · Excel: "บันทึกเป็น" → **CSV UTF-8** หรือเก็บเป็น `.xlsx` ก็ได้
   (CSV ธรรมดาจาก Excel ภาษาไทยก็อ่านได้ สคริปต์จะลองรหัส cp874 ให้)
2. วางไฟล์ไว้ใน `data/eval/inputs/` — โฟลเดอร์ `data/` ไม่อยู่ใน git เพราะไฟล์คำตอบมีชื่อและอีเมล
3. ผลออกที่ `data/eval/<ชื่อคำสั่ง>/` (เปลี่ยนได้ด้วย `--out`) ในตารางผู้ตอบจะเป็น E1…, R1… ไม่มีชื่อหรืออีเมล
4. ไฟล์แม่แบบอยู่ใน [`templates/`](templates/) แถวที่ขึ้นต้นด้วย `EXAMPLE` เป็นตัวอย่าง สคริปต์ข้ามให้ ลบทิ้งหรือเขียนทับได้
5. ลองทุกคำสั่งกับข้อมูลสมมติใน [`examples/`](examples/) ก่อนได้ (คำสั่งอยู่ท้ายไฟล์นี้)

## 1. IOC — `eval/ioc.py`

```bash
python -m eval.ioc data/eval/inputs/ioc.csv
```

รับได้ 2 แบบ
- **แบบ Google Forms (wide):** 1 แถวต่อผู้เชี่ยวชาญ 1 ท่าน คอลัมน์คะแนนต้องมี**รหัสข้อ**ในหัวคอลัมน์ เช่น `C1-1 สิ่งที่วัด…`, `C1.2`, `C1 ข้อ 2`
  หรือขึ้นต้นด้วยเลขข้อตามแบบฟอร์ม `1.` … `16.` (เลขข้อตรงกับ `form_no` ใน [`templates/ioc_items.csv`](templates/ioc_items.csv))
  คำตอบเขียนแบบ `+1 (สอดคล้อง)` / `−1` ได้ สคริปต์อ่านตัวเลขด้านหน้า
  คอลัมน์ข้อเสนอแนะ = หัวคอลัมน์มีคำว่า "ข้อเสนอแนะ" + รหัสข้อหรือรหัสเกณฑ์ (`ข้อเสนอแนะ เกณฑ์ C1`)
- **แบบยาว (long):** คอลัมน์ `expert, item, score, comment` ([`templates/ioc_responses.csv`](templates/ioc_responses.csv))

ผล: IOC = ΣR / N ต่อข้อ, ผ่านเมื่อ IOC ≥ 0.60 (ผลรวม ≥ 3 จาก 5 ตามแบบ v0.9 จำนวน 16 ข้อ) และแสดงคอลัมน์ "ผ่านที่ 0.50" ประกอบ ·
เปลี่ยนเกณฑ์ด้วย `--pass-min 0.5` · ถ้าบางท่านเว้นบางข้อ สคริปต์จะหยุดและบอกข้อที่ขาด ใช้ `--allow-missing` เพื่อคิดจากคะแนนที่มี

## 2. การกระจายของค่าและค่าขอบระดับที่แนะนำ — `eval/calibrate.py`

```bash
python -m eval.calibrate                       # อ่าน data/runs/*/result.json ทั้งหมด
python -m eval.calibrate --config-version thresholds-v0 --reference S01 web
```

- ฉากอ่านจากชื่อโฟลเดอร์ (`sc02_G07_P05_S05_T01` → S05, รอบจากหน้าเว็บ `s_…` → web) คิดเฉพาะการ์ดที่วิเคราะห์ได้
- ตาราง: สถิติ n, ต่ำสุด, P10, P25, มัธยฐาน, เฉลี่ย, SD, P75, P90, สูงสุด ของค่าที่ใช้ตัดระดับ (ค่าประกอบทั้งหมดอยู่ใน CSV) ·
  จำนวนคลิปในแต่ละระดับตามขอบ v0 · ป้ายหัวข้อ C2 · **ฉากควบคุมเทียบกับ S01** (เช่น S03 พูดช้าต้องได้พยางค์/วินาทีต่ำกว่า S01)
- **ค่าขอบที่แนะนำ** มาจากเปอร์เซ็นไทล์ของการซ้อมธรรมชาติ (S01 + รอบจากเว็บ) เท่านั้น เพราะฉากอื่นถูกสั่งให้ทำพฤติกรรมนั้น
  เขียนลง `data/eval/calibrate/thresholds-v1-suggested.yaml` (รูปแบบเดียวกับ `levels:` ใน thresholds-v0) **ไม่เขียนทับ config เอง**
  ไม่แนะนำ T1 (ขอบเป็นร้อยละของเวลาเป้าหมายตามข้อกำหนดสาขา) และ C1 C2 (ขอบตามกติกาหัวข้อในรูบริก)
- ข้อควรระวัง: ค่าแนะนำแบ่งกลุ่มอ้างอิงเป็นส่วนเท่า ๆ กันโดยปริยาย (ราวหนึ่งในสี่อยู่ระดับ 4 เสมอ) จึงเป็นแค่จุดเริ่มคุย
  ตัดสิน v1 ร่วมกับข้อเสนอแนะ IOC และความสอดคล้องกับอาจารย์ · กลุ่มอ้างอิงน้อยกว่า 10 คลิปจะมีคำเตือน

## 3. ความแม่นยำของการวัด — `eval/measurement_eval.py`

```bash
python -m eval.measurement_eval --values data/eval/inputs/gt_values.csv
python -m eval.measurement_eval --values gt_values.csv --events gt_events.csv --topics gt_topics.csv
```

`clip_id` = ชื่อโฟลเดอร์ใน `data/runs` ของคลิปนั้น (เช่น `sc02_G07_P05_S05_T01`) ไฟล์ใดไม่มีก็ข้ามได้

| ไฟล์ | คอลัมน์ | กรอกอย่างไร |
|---|---|---|
| [`gt_values.csv`](templates/gt_values.csv) | `clip_id, rater,` แล้วคอลัมน์ชื่อ `<รหัสเกณฑ์>.<ชื่อค่า>` | ตัวเลขรวมทั้งคลิป เช่น `S3.fillers` = จำนวนเสียงเติมและคำติดปากที่นับได้ตามกติกาด้านล่าง, `S2.long_pauses` = จำนวนช่วงเงียบ ≥ 2 วินาที, `T1.speech_span_s` = วินาทีตั้งแต่เริ่มพูดถึงพูดคำสุดท้าย, `N2.front_pct` = % เวลาที่หันหน้าตรง · ช่องว่าง = ไม่ได้นับ · ชื่อค่าต้องตรงกับใน `result.json` |
| [`gt_events.csv`](templates/gt_events.csv) | `clip_id, criterion, start_s, end_s, label` | 1 แถวต่อ 1 เหตุการณ์ (S2 ช่วงหยุดยาว, S3 เสียงเติมหรือคำติดปาก — ใส่คำที่ได้ยินในช่อง `label`, N1 ช่วงมือนิ่งต่อเนื่อง) เวลาเป็นวินาทีจากต้นคลิป · ถ้าฟังทั้งคลิปแล้วไม่พบเลย ใส่ 1 แถวที่เว้น `start_s` |
| [`gt_topics.csv`](templates/gt_topics.csv) | `clip_id, topic_id, label` | ป้ายของแต่ละหัวข้อตามที่ฟังจริง: `clear` / `brief` / `not_mentioned` |

ตามแผน (PLAN, D-040) งานขั้นต่ำคือ 1 คนฟัง 5 คลิป กรอกแค่ `gt_values.csv` (S3.fillers, S2.long_pauses) ส่วนเวลารายเหตุการณ์และป้ายหัวข้อเป็นของเสริม

ตัวชี้วัด
- **ค่าต่อเนื่อง:** MAE (คลาดเฉลี่ยกี่หน่วย), MAPE (คลาดเฉลี่ยกี่ % ไม่นับคลิปที่คนนับได้ 0), RMSE (ลงโทษความคลาดมากหนักกว่า),
  ระบบ − คน (ระบบนับเกินหรือขาด), Pearson r / Spearman ρ (ขึ้นลงตามกันไหม ต้องมี ≥ 3 คลิป)
- **เหตุการณ์ (ระดับเหตุการณ์):** จับคู่เวลาเริ่มของระบบกับคนแบบหนึ่งต่อหนึ่ง ห่างไม่เกิน tol (S2 S3 0.5 วินาที, N1 1 วินาที) →
  Precision (ที่ระบบพบ ถูกกี่ %), Recall (ที่คนพบ ระบบพบกี่ %), F1
- **เหตุการณ์ (ระดับช่วงเวลา):** แบ่งคลิปเป็นช่วงละ 0.5 วินาที ช่วงละมี/ไม่มีเหตุการณ์ → Accuracy, Cohen's κ (ตรงกันเกินกว่าโอกาสบังเอิญแค่ไหน), Precision, Recall, F1
- **ป้าย C2:** ตารางความสับสน, Accuracy, Precision/Recall/F1 รายป้าย, macro-F1, Cohen's κ, QWK (นับว่า "ไม่ได้กล่าวถึง < บางส่วน < ชัดเจน")
- การ์ดที่ระบบวิเคราะห์ไม่ได้จะไม่นำมาคิด และแจ้งในหัวข้อ "หมายเหตุ"

## 4. ความสอดคล้องของระดับ 1–4 — `eval/agreement_and_sus.py levels`

```bash
python -m eval.agreement_and_sus levels data/eval/inputs/ratings.csv
```

- **แบบ Google Forms (wide):** 1 แถวต่อ ผู้ประเมิน × คลิป มีคอลัมน์ `rater` (หรือ "ผู้ประเมิน" / อีเมล), `clip_id` และคอลัมน์ละเกณฑ์ที่หัวคอลัมน์มีรหัส `C1` … `T1`
- **แบบยาว:** `clip_id, criterion, rater, level` ([`templates/ratings.csv`](templates/ratings.csv)) · ช่องว่างหรือ "วิเคราะห์ไม่ได้" = ไม่มีระดับ
- ระดับของระบบอ่านจาก `data/runs/<clip_id>/result.json` เอง (ถ้าในไฟล์มีผู้ประเมินชื่อ `system` จะใช้ค่านั้นแทน)
- ตัวชี้วัดต่อเกณฑ์และรวม: ระหว่างอาจารย์ — **Krippendorff's α (ordinal)**, % ตรงกัน, % ห่างไม่เกิน 1 ระดับ (เฉลี่ยทุกคู่) ·
  ระบบเทียบมัธยฐานของอาจารย์ — **% ตรงกัน, % ห่างไม่เกิน 1 ระดับ, QWK, Spearman ρ** · QWK เทียบอาจารย์ทีละท่านแล้วเฉลี่ย · α เมื่อนับระบบเป็นผู้ประเมินอีกคน (ข้อมูลประกอบ)

## 5. SUS — `eval/agreement_and_sus.py sus`

```bash
python -m eval.agreement_and_sus sus data/eval/inputs/sus_responses.csv
```

แม่แบบ: [`templates/sus_responses.csv`](templates/sus_responses.csv)

หาคอลัมน์ 10 ข้อจากหัวคอลัมน์ `Q1` … `Q10`, `ข้อ 1` …, หรือที่ขึ้นต้นด้วย `1.` … `10.` (ตามลำดับคำถามมาตรฐาน: ข้อคี่เชิงบวก ข้อคู่เชิงลบ)
ถ้าหัวคอลัมน์ไม่ตรง ใช้ `--items <คอลัมน์ 1> … <คอลัมน์ 10>` · คะแนนรายคน = (Σ(ข้อคี่ − 1) + Σ(5 − ข้อคู่)) × 2.5 ·
สรุป n, x̄, SD, มัธยฐาน, ต่ำสุด, สูงสุด, 95% CI (ขอบถูกจำกัดในช่วง 0–100 ตามนิยาม SUS) และการแปลผล (Bangor และคณะ 2008, 2009 — ตรวจกับบทความก่อนเขียนเล่ม) ·
คนที่ตอบไม่ครบ 10 ข้อจะไม่นำมาคิดและแจ้งไว้ท้ายตาราง

## ทดสอบ

```bash
python -m pytest eval/tests -q
```

สูตรทุกตัวอยู่ใน [`stats.py`](stats.py) ฟังก์ชันละสูตร พร้อม docstring บอกสูตรและแหล่งที่มา และทดสอบกับค่าที่คิดมือหรือค่าที่ตีพิมพ์
(เช่น Krippendorff's α ของตัวอย่างใน Krippendorff 2011: nominal 0.743, ordinal 0.815, interval 0.849)

> ในตาราง "—" หมายถึงคำนวณไม่ได้ เช่น ข้อมูลไม่พอ หรือไม่มีความแปรปรวน (ทุกคนให้ระดับเดียวกันหมด ค่า κ / QWK / α จะเป็น 0/0 จึงไม่รายงานเป็น 1.0)


สำหรับผลที่ใช้ทำรายงาน ให้เลือก run ID ที่ตรวจแล้วหนึ่งบรรทัดต่อรอบในไฟล์ข้อความ แล้วใช้
`python -m eval.snapshot --runs data/runs --ids data/eval/ids.txt --out data/eval/frozen`
จากนั้นใช้ `--runs data/eval/frozen` ในเครื่องมือประเมิน ตัวอ่านจะตรวจรายการและ SHA-256 จาก manifest
และหยุดหากมีรหัสซ้ำ ไม่ต้องคัดลอกไฟล์สื่อเพื่อทำ snapshot; ผล JSON ยังต้องอยู่ในที่จำกัดสิทธิ์
